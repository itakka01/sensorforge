SensorForge image-motion integration - 2026-09-18

Default / regression policy
- Existing direct radar/OT2 recording remains the default.
- image_motion_enabled=0 and motion_recording_decision=direct preserve the old path.
- Enable and tune from WebConfig -> Sensor -> Image motion.

Analysis path
- Existing recording JPEG frame is decoded at 1/8 scale to RGB565.
- 1024x768 therefore analyzes 128x96 pixels.
- Pixels are converted to grayscale and accumulated directly into a 20x15 block grid.
- No ML/AI and no full-resolution RGB buffer are used.
- ROI is a compact 300-bit / 38-byte mask persisted as 76 hexadecimal characters.

Detection
- adaptive per-block background model
- learned per-block noise floor
- sensitivity mapping 1..10
- minimum connected motion area
- 8-neighbor connected-component filtering
- confirmation frames and release hysteresis
- global mean / global changed-area light-change rejection
- faster controlled background adaptation after global light changes
- darker scenes receive an additional threshold margin

Wake / recording integration
- Radar/OT2 remains the low-power wake source.
- image_verify is a recording decision after a real sensor trigger.
- software simulated motion remains direct so it can still deterministically test the recorder.
- analyzer failure is fail-open for real events: recording proceeds rather than silently missing an event.
- a rejected trigger is latched until physical radar motion clears, avoiding repeated analysis during the 2 s radar hold.
- existing thermal, storage, recording safety cooldown, WebConfig pause/preview and recorder gates are unchanged.

WebConfig
- Sensor -> Image motion
- live image with 20x15 drawable ROI overlay
- Select all / Clear all / Invert
- settings save through existing SD + LittleFS config persistence
- test mode never starts an automatic recording
- diagnostic JSON includes analyze_frame_ms, decode_ms, active_roi_blocks,
  changed_blocks, largest_cluster_blocks, changed_area_pct, global_change_pct,
  global_mean, global_mean_delta, motion_score, block_threshold,
  minimum_motion_blocks, image_motion_state, reject_reason, background_state,
  confirm_counter, release_counter and motion_active.

Not implemented intentionally
- A separate physical PIR wake source is NOT added yet. Current XIAO board_config.h aliases PIR_PIN to the LD2410S OT2 GPIO4. A future dedicated PIR requires the actual selected GPIO and active polarity; those were not guessed.

First hardware test order
1. Flash with defaults (direct + image motion disabled) and verify no radar/recording regression.
2. Open Sensor -> Image motion. Draw ROI and save settings with image analysis enabled but decision still direct.
3. Use Test image analysis; record timing/diagnostics for person, empty room, lighting changes and night scene.
4. Only after measured values look sane, switch Recording decision to Sensor trigger + image verification.
5. Measure wake-to-decision, wake-to-first-written-frame, false rejects/accepts, current draw and temperature.

Security note
- The uploaded development private license PEM is intentionally not copied into this source package.
